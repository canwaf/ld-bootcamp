Learn Linked Data

Use this course to learn how to publish data on the web so that it joins up with everyone else’s, and how to ask questions of it once it does.

The course starts from something you already do: joining two tables on a key. It follows that idea, one step at a time, until the key is a URI that anyone on the web can use, look up and query.

In this course you’ll learn how to:

  • turn the keys and codes in your tables into URIs
  • decide who mints a URI and keep it stable
  • describe things as RDF using shared vocabularies
  • serve one resource in many formats with content negotiation
  • query graphs with SPARQL

Every example follows one water quality sampling point, the samples taken there and the observations made on them, so each module builds on the one before.

Before you start

You’ll find the course easier if you’ve joined two tables before, in a spreadsheet lookup or a SQL query.

You’ll need:

  • a web browser
  • a terminal with curl, from Module 4 onwards

Each module ends with a short quiz. Choose an answer and you’ll see straight away whether it’s right, and why. You can change your answer as often as you like.

Course contents

  1. Module 1: From keys to URIs Why codes break when they leave their table, and how a URI carries its meaning with it. Available
  2. Module 2: Authority, minting and persistence Who is responsible for a URI, how to mint one, and why identifiers should only change when the thing they identify does. Available
  3. Module 3: Triples and vocabularies Statements as triples, and the vocabularies that describe catalogues, concepts and observations: DCAT, SKOS and SOSA. Available
  4. Module 4: Serialisation and content negotiation One graph written as Turtle, N-Triples, RDF/XML, JSON-LD and RDFa, and one URI serving different formats on request. Available
  5. Module 5: Querying with SPARQL Asking questions of a graph: patterns, joins on URIs, BIND, string functions, UNION and OPTIONAL. Coming soon
